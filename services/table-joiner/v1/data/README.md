# Sample data

The tables are synthetic and are generated by `tables.py` with fixed seeds, so every worker and every run sees
exactly the same rows. Nothing is downloaded and nothing but this file lives in `data/`.

- **Customers:** 100 000 rows with `customer_id`, `group` and `discount`. Customers are spread evenly over
  `group_count` groups in a seeded random order, so every group has at least one customer.
- **Orders:** 16 batches (the samples), each with `data_quality` rows of `customer_id`, `quantity` and
  `unit_price`. Half of the orders go to a few popular customers (Pareto), half are spread evenly, and about
  2 % name a customer that does not exist, so the join really drops rows.

The tables depend on the knobs and not on the item, so `init_worker` builds them once per worker. At the
largest setting (1 000 000 orders per batch) the sixteen batches hold about 300 MB, and one join creates a few
hundred megabytes of intermediate columns.
